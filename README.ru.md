# Obsidian Image Optimizer

[English](README.md) | [Русский](README.ru.md)

Делает картинки в заметках [Obsidian](https://obsidian.md) лёгкими и локальными: картинки из интернета скачиваются в хранилище и сжимаются в WebP с качеством, при котором разница не видна глазу (**40** по умолчанию), — обычно **в 5–8 раз меньше** для скриншотов и картинок из интернета. Ссылки в заметках обновляются автоматически.

Проект состоит из двух частей:
- **Плагин для Obsidian** (`obsidian-plugin/`) — работает внутри Obsidian на **Windows, macOS, Linux, Android и iOS**, без установки чего-либо в операционную систему: кодировщик WebP (libwebp — библиотека, на которой построен `cwebp`) скомпилирован в WebAssembly и встроен в плагин.
- **Утилита командной строки** (Go) — для пакетной обработки и автоматизации вне Obsidian.

## 📱 Плагин для Obsidian

### Что делает
- **Скачивает картинки из интернета** (`![](https://…)` и `<img src="https://…">`) в выбранную папку и переводит ссылки на локальные файлы. Принимаются только настоящие картинки: HTML-страница «hotlinking denied» никогда не заменит вашу ссылку.
- **Сжимает в WebP** — JPG, PNG и BMP в WebP, **анимированные GIF в анимированный WebP**. Сжатая картинка используется, только если она меньше хотя бы на 5% (настраивается), иначе остаётся оригинал.
- **Сжимает картинки, уже лежащие в хранилище**: WebP сохраняется рядом с оригиналом, все ссылки на него во всех заметках переписываются (встраивания, ссылки, свойства; размеры вроде `|200` сохраняются), а оригинал переносится в папку `.trash` хранилища, откуда его можно восстановить. Если оригинал ещё где-то упоминается — в canvas, свойстве, обычном тексте, — он остаётся на месте.
- **Сжимает при вставке и перетаскивании**: вставленный скриншот сразу сохраняется в WebP, картинки из вставленного текста скачиваются.
- **Не подвешивает интерфейс**: сжатие идёт в фоновом потоке, по одной картинке; у долгой обработки есть прогресс и кнопка остановки.

### Установка
Пока плагина нет в каталоге сообщества, установите его через **BRAT**:
1. Установите и включите плагин сообщества **BRAT**.
2. Выполните **BRAT: Add a beta plugin for testing**, введите `ibrusi/obsidian-local-image-small` и выберите последнюю версию.
3. Включите **Image Optimizer** в *Настройки → Сторонние плагины*.

Вручную: скачайте `obsidian-image-optimizer.zip` из [последнего релиза](https://github.com/ibrusi/obsidian-local-image-small/releases), распакуйте в `<хранилище>/.obsidian/plugins/` (папка `.obsidian` скрытая) и включите плагин.

### Использование
Откройте палитру команд (`Ctrl/Cmd+P` на компьютере; на телефоне — свайп вниз по заметке или через меню) и наберите **image**:

| Команда | Что делает |
| :--- | :--- |
| **Optimize images in the current note** | Скачивает картинки из интернета и сжимает картинки заметки. |
| **Optimize images in the whole vault** | То же для всех заметок, с прогрессом и кнопкой «Stop». |
| **Stop image optimization** | Останавливает текущую обработку. Готовые картинки остаются готовыми. |

Если включено **Convert on paste and drop** (по умолчанию), вставленные и перетащенные картинки обрабатываются без команд.

### Настройки
| Настройка | По умолчанию | Описание |
| :--- | :--- | :--- |
| Image folder | `Attachments` | Куда сохраняются скачанные и вставленные картинки: `Attachments` — папка рядом с заметкой; `/Attachments` — одна папка в корне хранилища; пусто — папка самой заметки. Сжатые локальные картинки остаются рядом с оригиналами. |
| Quality | `40` | Качество WebP, 1–100. |
| Compression effort | `4` | Метод libwebp, 0–6. `6` даёт файлы примерно на 5% меньше, но в разы медленнее — заметно на телефонах. |
| Minimum saving, % | `5` | Оставлять оригинал, если WebP меньше на меньший процент. |
| GIF | Convert to WebP | Или оставлять GIF как есть. |
| Convert images already in the vault | вкл. | Команды сжимают и локальные JPG/PNG/BMP/GIF и переносят оригиналы в `.trash`. |
| Convert on paste and drop | вкл. | См. выше. |
| Reuse identical files | вкл. | Если файл с таким же именем в папке назначения (`pic.webp`, `pic-1.webp`, …) содержит точно такие же байты, ссылка ставится на него, а копия не сохраняется. Выкл.: каждая картинка сохраняется новым файлом. |
| Maximum download, MB | `30` | Более крупные загрузки отклоняются. |
| Maximum image size, megapixels | `50` | Более крупные картинки остаются как есть (для анимации — ширина × высота × кадры), чтобы не исчерпать память телефона. |
| Allow private network addresses | выкл. | По умолчанию ссылки на `localhost`, `*.local` и частные, loopback и link-local IP-адреса отклоняются, чтобы заметка из недоверенного источника не могла прощупать вашу сеть. |
| Write a log note | выкл. | Дописывает подробности каждого запуска в `image-optimizer-log.md`. |

Настройки плагина хранятся в `.obsidian/plugins/obsidian-image-optimizer/data.json`; если ваша синхронизация не переносит `.obsidian/plugins`, задайте их на каждом устройстве.

### Полезно знать
- EXIF-метаданные (дата, GPS) в сжатых картинках не сохраняются; поворот фотографий с телефона применяется к пикселям.
- Файлы никогда не перезаписываются: новые файлы получают свободное имя (`pic.webp`, `pic-1.webp`, …). Если файл с таким именем уже содержит точно такие же байты (одна и та же картинка в двух заметках), он переиспользуется вместо сохранения копии (настройка *Reuse identical files*).
- Ссылки внутри блоков кода, инлайн-кода и комментариев не трогаются. Открытые в редакторе заметки сохраняются перед изменением.
- WebP повторно не перекодируется, поэтому повторный запуск не ухудшает качество.

## ⌨️ Утилита командной строки (Go)

Утилита обрабатывает хранилище из терминала с помощью внешних кодировщиков (`cwebp`, `ffmpeg`, `gifsicle`). Подходит для пакетной обработки, скриптов и запуска по расписанию.

1. **Скачивание картинок из интернета** в папку `attachments/` рядом с каждой заметкой. Принимаются только настоящие картинки.
2. **Конвертация в WebP** с настраиваемым качеством (по умолчанию 40). Фото с телефона поворачиваются по EXIF-ориентации, цветовой профиль (ICC) сохраняется.
3. **Умное сжатие GIF**: анимированный WebP (`gif2webp`, `ffmpeg`), lossy GIF через `gifsicle` и встроенный Go-оптимизатор палитры как запасной вариант.
4. **Строгая проверка размера**: сжатая картинка используется **только если она строго меньше оригинала**.
5. **Безопасная замена ссылок**: `![alt](url)`, `<img src="url">` и `![[url]]`; блоки кода, инлайн-код и комментарии не трогаются.
6. **Без перезаписи файлов**: новые файлы всегда получают свободное имя.
7. **Опциональная оптимизация локальных картинок** (`--optimize-local`) с обновлением **всех** заметок, где картинка встроена.

---

### 💡 Решение проблемы с GIF

> **Ключевой факт**: GIF **можно** перевести в WebP!
> WebP поддерживает покадровую анимацию (**Animated WebP**), а Chromium и Electron (на которых построен Obsidian) показывают её нативно.

| Режим (`--gif-mode`) | Что происходит |
| :--- | :--- |
| `auto` (по умолчанию) | Конвертация в анимированный WebP (`gif2webp`, затем `ffmpeg`). Если это невозможно или результат не меньше — GIF оптимизируется как GIF (`gifsicle`, палитра `ffmpeg`, встроенный оптимизатор на Go). |
| `webp` | Только анимированный WebP; если не получилось или результат не меньше — остаётся исходный GIF. |
| `optimize` | Формат `.gif` сохраняется: `gifsicle -O3 --lossy=80`, генерация палитры `ffmpeg` или встроенный оптимизатор на Go. |
| `keep` | Любые GIF (статичные и анимированные) не трогаются. |

Типичная экономия: анимированный WebP **60–85%**, lossy-GIF **30–55%**. Дополнительные настройки: `--gif-colors` (размер палитры), `--gif-lossy`, `--gif-max-width` (уменьшение широких GIF; поддерживается `gifsicle`/`ffmpeg`), `--gif-drop-frames` (только встроенный оптимизатор).

Во всех режимах действует строгая проверка размера: если результат не меньше, остаётся исходный GIF.

### 🚀 Установка и сборка

#### 1. Системные зависимости (нужны для WebP)
Для конвертации JPEG/PNG/TIFF/BMP → WebP требуется `cwebp` (пакет `webp`) или `ffmpeg`. Без них оптимизируются только GIF (встроенным оптимизатором на Go), а при запуске выводится предупреждение.

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install -y webp gifsicle ffmpeg

# macOS (Homebrew)
brew install webp gifsicle ffmpeg

# Windows (Scoop / Chocolatey)
scoop install libwebp gifsicle ffmpeg
# или
choco install webp gifsicle ffmpeg
```

#### 2. Сборка бинарника (Go 1.23+)
```bash
git clone https://github.com/ibrusi/obsidian-local-image-small.git
cd obsidian-local-image-small
go build -o bin/obsidian-img-opt ./cmd/obsidian-img-opt
```

*(Опционально)* скопируйте бинарник в `/usr/local/bin`:
```bash
sudo cp bin/obsidian-img-opt /usr/local/bin/
```

### 🛠️ Использование через CLI

#### Обработка одной заметки:
```bash
obsidian-img-opt --vault "/path/to/vault" --file "/path/to/vault/My Article.md"
```
Рекомендуется передавать `--vault` вместе с `--file`: хранилище ограничивает, какие файлы можно трогать, и нужно для безопасной замены локальных оригиналов (см. ниже). Один `--file` тоже работает, но тогда локальные оригиналы никогда не заменяются.

#### Обработка всего хранилища (рекурсивно):
```bash
obsidian-img-opt --vault "/path/to/vault"
```

#### Настройка качества WebP (по умолчанию 40):
```bash
obsidian-img-opt --vault "/path/to/vault" --quality 60
```

#### Оптимизация и локальных, и удалённых картинок:
```bash
obsidian-img-opt --vault "/path/to/vault" --optimize-local
```

#### Предпросмотр (ничего не скачивается и не записывается):
```bash
obsidian-img-opt --vault "/path/to/vault" --optimize-local --dry-run
```

#### Машиночитаемый вывод:
```bash
obsidian-img-opt --vault "/path/to/vault" --output json
```

#### Все доступные флаги

| Флаг | По умолчанию | Описание |
| :--- | :--- | :--- |
| `--vault` (синоним `--dir`) | текущая папка | Хранилище Obsidian: обрабатывается рекурсивно или служит корнем для `--file`. |
| `--file` | `""` | Один Markdown-файл для обработки. |
| `--quality` | `40` | Качество lossy WebP (1–100). |
| `--attached-dir` (синоним `--attachments`) | `attachments` | Папка для скачанных картинок относительно заметки. Не может выходить за пределы папки заметки. |
| `--backup-dir` (синоним `--backup`) | `.originals_backup` | Папка (внутри папки изображения), куда переносятся заменённые оригиналы. |
| `--keep-backup` | `true` | Переносить заменённые оригиналы в `--backup-dir`; при `--keep-backup=false` они удаляются. |
| `--optimize-local` | `false` | Оптимизировать также существующие локальные JPG/PNG/GIF/BMP/TIFF. |
| `--link-format` | `markdown` | Синтаксис новых ссылок на скачанные картинки: `markdown` (`![](...)`) или `wikilink` (`![[...]]`). |
| `--gif-mode` | `auto` | Обработка GIF: `auto`, `webp`, `optimize`, `keep`. |
| `--gif-lossy` | `80` | Уровень lossy-сжатия gifsicle (0–200). |
| `--gif-colors` | `128` | Максимум цветов палитры, если GIF остаётся GIF (2–256). |
| `--gif-max-width` | `0` | Уменьшать GIF шире указанного числа пикселей (`0` — не менять размер). |
| `--gif-drop-frames` | `false` | Выбрасывать каждый второй кадр длинных анимаций (встроенный оптимизатор). |
| `--dry-run` | `false` | Показать план без скачивания и записи. |
| `--output` | `text` | `text` или `json` (одна JSON-сводка в stdout, прогресс — в stderr). |
| `--verbose` | `false` | Подробный лог. |
| `--timeout` | `30` | HTTP-таймаут одной загрузки, секунды. |
| `--tool-timeout` | `300` | Таймаут одного запуска внешнего кодировщика, секунды. |
| `--max-download-mb` | `50` | Максимальный размер скачиваемой картинки, МБ. |
| `--max-pixels` | `100000000` | Максимальный размер декодирования в памяти (ширина × высота × кадры). |
| `--allow-private-hosts` | `false` | Разрешить загрузку с localhost, из частных и link-local сетей. |
| `--concurrency` | `4` | Сколько изображений обрабатывается параллельно (1–64). |

Утилита настраивается только флагами командной строки; из переменных окружения читаются лишь стандартные `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY`.

#### Коды выхода

| Код | Значение |
| :--- | :--- |
| `0` | Успех. |
| `1` | Фатальная ошибка (неверные флаги, хранилище не найдено, …). |
| `2` | Работа завершена, но часть изображений или заметок не обработана (см. предупреждения). |
| `130` | Прервано (Ctrl+C / SIGTERM). |

### 🛡️ Гарантии безопасности

- **Без перезаписи.** Результаты пишутся во временные файлы и публикуются под свободным именем; существующие файлы никогда не перезаписываются.
- **Локальный оригинал заменяется последним.** С `--optimize-local` сначала создаётся оптимизированная копия, затем переписываются все заметки, встраивающие картинку, и только после этого оригинал переносится в `--backup-dir`. Оригинал остаётся на месте, если хотя бы одну заметку не удалось обновить, если `--vault` не задан или если его имя файла **всё ещё упоминается где-либо** в хранилище (свойства, canvas, обычные `[[ссылки]]`, текст).
- **Только внутри хранилища.** Ссылки за пределы хранилища и символические ссылки игнорируются; `--attached-dir`/`--backup-dir` не могут выйти за пределы папки заметки.
- **Недоверенные загрузки.** Сохраняются только ответы, которые действительно являются изображениями; размер ограничен (`--max-download-mb`); GIF проверяется до декодирования (`--max-pixels`); у внешних инструментов есть таймаут.
- **Защита от SSRF.** По умолчанию запрещены загрузки с `localhost`, частных (`10.x`, `192.168.x`, …), link-local (включая адрес облачных метаданных `169.254.169.254`) и CGNAT-адресов — заметка из недоверенного источника не сможет прощупать вашу сеть. Для картинок из интранета используйте `--allow-private-hosts`. При настроенном HTTP-прокси целевой хост проверяется через DNS до запроса (best effort: прокси резолвит имя повторно).
- **Одновременное редактирование.** Каждая заметка перечитывается непосредственно перед записью, поэтому правки, сделанные во время загрузки, сохраняются. Оставшееся окно — миллисекунды, а не ноль: не редактируйте ту же самую заметку во время пакетной обработки.

Известные ограничения: блоки кода с отступом в 4 пробела не распознаются как код (в Obsidian такой отступ обычно означает вложенный элемент списка); локальные картинки, у которых оптимизированная версия не меньше, проверяются заново при каждом запуске.

## 🧪 Разработка

### Плагин
```bash
cd obsidian-plugin
npm ci
npm run typecheck
npm test               # юнит-тесты (Node 22.18+)
npm run test:browser   # кодировщики в Chromium и WebKit (нужны браузеры Playwright)
npm run build          # main.js
```
Релиз публикуется CI для каждой новой версии в `manifest.json` (версию в `package.json` держите такой же); версии с суффиксом вроде `2.0.0-beta.3` — pre-release.

### Утилита командной строки

```bash
gofmt -l .                 # вывод должен быть пустым
go vet ./...
go test -race -cover ./... # интеграционные тесты пропускаются без cwebp/gif2webp
```

CI (`.github/workflows/ci.yml`) дополнительно запускает `staticcheck`, а также собирает и тестирует плагин в Chromium и WebKit.
