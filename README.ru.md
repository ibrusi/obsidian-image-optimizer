# Obsidian Image Optimizer

[English](README.md) | [Русский](README.ru.md)

Оптимизирует изображения в заметках [Obsidian](https://obsidian.md) и сохраняет их локально: изображения из интернета скачиваются прямо в хранилище, а локальные файлы конвертируются в формат WebP с качеством, визуально неотличимым от оригинала (по умолчанию **40**). Это уменьшает размер файлов скриншотов и веб-изображений обычно **в 5–8 раз**. Ссылки в заметках обновляются автоматически. Поддерживается обработка одной заметки, выбранной папки со всеми подпапками или всего хранилища целиком.

Это **плагин для Obsidian** (`obsidian-plugin/`), работающий на **Windows, macOS, Linux, Android и iOS**. Он полностью автономен и не требует установки сторонних утилит в операционную систему: энкодер WebP (библиотека libwebp, лежащая в основе `cwebp`) скомпилирован в WebAssembly и встроен непосредственно в плагин.

## 📱 Плагин для Obsidian

### Возможности
- **Три области охвата**: сохраняет и оптимизирует изображения для **текущей заметки**, для **выбранной папки со всеми вложенными подпапками** или сразу для **всего хранилища** — везде действуют единые правила обработки (см. раздел [Использование](#использование)).
- **Скачивание изображений из сети** (`![](https://…)` и `<img src="https://…">`): сохраняет файлы в указанную папку и перенаправляет ссылки в заметках на локальные копии. Проверяется фактический тип контента: заглушки и HTML-страницы с ошибкой хотлинкинга («hotlinking denied») никогда не заменят исходную ссылку. Сторонние виджеты вроде роликов YouTube и твитов, оформленные через `![](…)`, остаются без изменений.
- **Сохранение SVG без конвертации** (формулы, схемы, диаграммы): векторная графика сохраняет идеальную чёткость и обычно весит меньше растровой копии в WebP, поэтому плагин никогда её не перекодирует.
- **Скачивание PDF-файлов (опционально, по умолчанию отключено)**: при включении настройки *Скачивать PDF* документы, встроенные в заметки (`![](https://….pdf)`) или указанные обычными ссылками (`[текст](https://….pdf)`), скачиваются как есть в папку вложений, а ссылки переводятся на сохранённые локальные копии.
- **Эмуляция браузера и умная обработка повторов.** Ссылки с постоянными ошибками (404, 403 или ответ, не являющийся изображением) не запрашиваются повторно при обработке других заметок в рамках текущей сессии; временные сетевые сбои и таймауты при этом могут повторяться, а каждый новый запуск оптимизации проверяет все ссылки заново. Запросы отправляются с заголовками браузера (URL из frontmatter-свойства `source` заметки передаётся в качестве заголовка `Referer`). Если сайт больше не отдаёт файл с расширением `.webp` (код 404 или 403 от хранилищ вроде S3), плагин пытается загрузить исходный формат (`.jpg`, `.jpeg`, `.png`, `.gif` по тому же адресу) — это решает проблему веб-клипперов, которые нередко сохраняют ссылки на временные WebP-версии сайтов.
- **Конвертация в WebP**: сжимает JPG, PNG и BMP в WebP, а **анимированные GIF — в анимированный WebP**. Для PNG, BMP и GIF плагин автоматически выбирает алгоритм (lossless или lossy) на основе анализа содержимого: графика с ограниченной палитрой и минимумом изменений между кадрами (скриншоты, схемы, записи экрана) кодируется без потерь (lossless, пиксель в пиксель); полноцветные изображения и динамичные сцены (фотографии, рендеры, видеоролики) — с потерями (lossy). Если выбранный режим не даёт выигрыша в размере, плагин пробует альтернативный; в спорных случаях изображение кодируется обоими способами, и выбирается файл наименьшего размера. Файлы JPG сжимаются только с потерями (lossy). Оптимизированный файл заменяет оригинал только при уменьшении размера не менее чем на 5% (порог настраивается); в противном случае сохраняется исходный файл.
- **Оптимизация уже существующих файлов в хранилище**: сжатая WebP-версия сохраняется рядом с исходным файлом, все ссылки на него во всех заметках автоматически обновляются (встраивания, прямые ссылки, frontmatter-свойства; модификаторы размера вроде `|200` сохраняются), а оригинал перемещается в корзину хранилища (`.trash`), откуда его всегда можно восстановить. Если исходный файл всё ещё где-либо упоминается (на холстах Canvas, в метаданных или в обычном тексте), он остаётся на месте и не удаляется.
- **Предотвращение дубликатов** (настройка *Не сохранять одинаковые файлы*, включена по умолчанию). При повторном появлении того же изображения — в другой заметке, при повторной вставке, копировании локального файла или синхронизации с другого устройства — ссылка привязывается к уже имеющемуся файлу в хранилище без лишнего сохранения и перекодирования. Механизм работает в три этапа и одинаково эффективен для скачиваемых, вставляемых и локальных файлов:
  1. **Поиск по цифровому отпечатку до кодирования.** Каждый файл, сохраняемый плагином, содержит в имени *тег оригинала*: первые 16 шестнадцатеричных символов SHA-256 хеша **исходных** байтов (до сжатия: скачанного файла, фрагмента из буфера или локального оригинала), например `photo-3fa9c2e1b7d04a85.webp`. Для каждого нового изображения плагин вычисляет такой же тег и ищет его среди имён файлов всего хранилища. Поиск выполняется только по именам из оперативной памяти Obsidian, поэтому чтение файлов с диска для несовпадающих имён исключено. Кандидаты сортируются по приоритету: сначала файлы WebP, затем по кратчайшему пути к файлу, затем по алфавиту.
  2. **Верификация кандидата.** Тег представляет собой лишь 64 бита хеша, и имя любого стороннего файла теоретически может оканчиваться на 16 шестнадцатеричных символов. Поэтому найденный кандидат считывается и проходит валидацию перед использованием. Файл в исходном формате (оригинал, сохранённый без конвертации) должен совпадать с новым **побайтно**. Файл WebP, полученный из этого оригинала, должен иметь **ту же ширину и высоту** (для JPEG допускаются инвертированные размеры с учётом EXIF-ориентации, применённой к пикселям). Любое несоответствие отклоняет кандидата, поэтому случайное совпадение имён никогда не приведёт к подстановке чужого изображения в заметку.
  3. **Побайтное сравнение после кодирования.** Если по тегу совпадений не найдено, изображение кодируется, после чего плагин ищет в хранилище файл с **идентичным побайтовым содержимым**: с тем же расширением и **в точности таким же размером** (размеры проверяются по метаданным в памяти Obsidian, файлы других размеров с диска не читаются). Далее кандидаты побайтно сравниваются (сначала файлы из целевой папки, затем остальные по алфавиту); первое совпадение считается окончательным. Это позволяет выявлять одинаковые изображения, полученные из формально разных источников (например, картинку, скопированную из браузера, которую буфер обмена пересохраняет в другой PNG, но которая сжимается в тот же WebP), а также файлы, сохранённые ранними версиями плагина без тегов.

  Переиспользованный файл никогда не модифицируется, не перемещается и не удаляется плагином, так как на него могут ссылаться другие заметки. При замене локального изображения на уже имеющийся WebP ссылки переключаются на существующий файл, а оригинал отправляется в корзину. Если файл переименован вручную, он теряет тег отпечатка: в этом случае при повторном добавлении он может быть сохранён ещё раз, но данные никогда не потеряются. Если настройка отключена, поиск и тегирование не производятся, имена не содержат хеш, и каждое изображение сохраняется как новый файл. Никаких дополнительных баз данных синхронизировать не требуется: все отпечатки хранятся прямо в именах файлов.
- **Оптимизация при вставке и Drag-and-Drop**: скриншот из буфера обмена моментально сохраняется в формате WebP, а изображения по ссылкам во вставленном тексте автоматически скачиваются и конвертируются.
- **Отзывчивый интерфейс без зависаний**: кодирование выполняется в фоновом воркере (Web Worker) последовательно по одному файлу. При длительных пакетных операциях отображается окно прогресса с возможностью прервать процесс.

### Установка
Из официального каталога сообщества (после публикации плагина): *Настройки → Сторонние плагины → Обзор*, найдите **Image Optimizer**, установите и включите его.

До официального релиза в каталоге или для тестирования предварительных версий плагин можно установить через **BRAT**:
1. Установите и включите плагин сообщества **BRAT**.
2. Вызовите команду **BRAT: Add a beta plugin for testing**, укажите репозиторий `ibrusi/obsidian-image-optimizer` и выберите последнюю версию.
3. Включите **Image Optimizer** в разделе *Настройки → Сторонние плагины*.

Ручная установка: скачайте архив `image-optimizer.zip` со страницы [последнего релиза](https://github.com/ibrusi/obsidian-image-optimizer/releases), распакуйте его в папку `<хранилище>/.obsidian/plugins/` (папка `.obsidian` является скрытой) и включите плагин в настройках Obsidian.

### Использование
Откройте палитру команд (`Ctrl/Cmd+P` на компьютере; на мобильных устройствах — свайп вниз внутри заметки или через боковое меню) и начните вводить **image** или **сжать**:

| Команда | Описание |
| :--- | :--- |
| **Сжать картинки в текущей заметке** | Скачивает веб-изображения и оптимизирует локальные файлы в открытой заметке. |
| **Сжать картинки в папке текущей заметки** | Выполняет оптимизацию для всех заметок в папке текущей заметки и её подпапках с отображением прогресса и кнопкой остановки. |
| **Сжать картинки во всём хранилище** | Выполняет оптимизацию для всех заметок хранилища с отображением прогресса и кнопкой остановки. |
| **Остановить сжатие картинок** | Прерывает текущий процесс оптимизации. Уже обработанные файлы сохраняются. |

Для обработки произвольной папки нажмите на неё правой кнопкой мыши в проводнике файлов (или удерживайте долгим нажатием на мобильном устройстве) и выберите пункт **Сжать картинки в этой папке**. Файлы определяются на основе ссылок в заметках выбранной папки: если в заметку встроено изображение, хранящееся в другой директории, оно также будет оптимизировано.

Если включена опция **Сжимать при вставке и перетаскивании** (по умолчанию), изображения из буфера обмена и перетаскиваемые файлы обрабатываются автоматически без вызова команд.

### Настройки
| Настройка | По умолчанию | Описание |
| :--- | :--- | :--- |
| Язык | Как в Obsidian | Английский или русский. По умолчанию плагин использует язык интерфейса Obsidian; если язык не поддерживается, включается английский. |
| Папка для картинок | `Attachments` | Путь для сохранения скачанных и вставленных изображений: `Attachments` — подпапка рядом с текущей заметкой; `/Attachments` — единая папка в корне хранилища; пустое значение — папка самой заметки. Оптимизированные локальные файлы сохраняются в той же папке, где находились их оригиналы. |
| Качество | `40` | Качество WebP при кодировании с потерями (lossy), от 1 до 100. На сжатие без потерь (lossless) этот параметр не влияет. |
| Степень сжатия | `4` | Уровень оптимизации libwebp (method), от 0 до 6. Значение `6` делает файлы примерно на 5% компактнее, но процесс кодирования занимает в несколько раз больше времени (что особенно ощутимо на смартфонах). |
| Минимальная экономия, % | `5` | Порог сжатия: оригинал сохраняется без изменений, если выигрыш в размере от конвертации в WebP составляет менее указанного процента. |
| GIF | Сжимать в WebP | Конвертировать анимированные GIF в анимированный WebP или сохранять исходные GIF-файлы без изменений. |
| Сжимать картинки, уже лежащие в хранилище | вкл. | При выполнении команд также оптимизировать существующие локальные файлы JPG, PNG, BMP и GIF, перемещая исходные файлы в корзину хранилища (`.trash`). |
| Сжимать при вставке и перетаскивании | вкл. | Автоматически оптимизировать изображения при вставке из буфера обмена и перетаскивании в редактор. |
| Не сохранять одинаковые файлы | вкл. | В имя каждого сохранённого файла внедряется цифровой отпечаток исходника. При повторном добавлении того же изображения (в другую заметку, дважды в один документ, копии локального файла или на другом устройстве) создаётся ссылка на уже существующий файл вместо создания дубликата, даже если настройки с тех пор изменились. При отключении: имена файлов формируются без отпечатка, каждое изображение сохраняется как новый файл. |
| Скачивать PDF | выкл. | При запуске команд или вставке текста плагин также скачивает внешние PDF-документы, встроенные (`![](https://….pdf)`) или прикреплённые ссылками (`[текст](https://….pdf)`), сохраняя их в папку вложений и заменяя ссылки на локальные пути (текст ссылки сохраняется). Учитываются только URL с расширением `.pdf` и подтверждённым MIME-типом PDF. К загрузкам применяется ограничение по размеру. При отключении: ссылки на сторонние PDF остаются без изменений. |
| Максимальный размер загрузки, МБ | `30` | Максимально допустимый размер скачиваемого файла. Загрузка файлов большего размера отклоняется. |
| Максимальный размер картинки, мегапикселей | `50` | Предел разрешения для оптимизации (для анимаций рассчитывается как: ширина × высота × количество кадров). Изображения большего размера сохраняются без конвертации для предотвращения переполнения оперативной памяти на мобильных устройствах. |
| Разрешить адреса локальной сети | выкл. | По умолчанию запросы к `localhost`, доменам `*.local`, а также частным, loopback и link-local IP-адресам блокируются в целях безопасности, чтобы заметки из непроверенных источников не могли сканировать вашу локальную сеть. |
| Вести журнал в заметке | выкл. | Записывает детальный отчёт о каждой операции в файл `image-optimizer-log.md` (на английском языке, для диагностики неполадок): версии плагина и Obsidian, операционную систему, список обработанных заметок и файлов, а при ошибках загрузки — полные сведения о запросах и ответах сервера (HTTP-статус, заголовки ответа, фрагмент страницы с ошибкой). |

Настройки плагина сохраняются в файле `.obsidian/plugins/image-optimizer/data.json`. Если используемая вами служба синхронизации не копирует каталог `.obsidian/plugins`, параметры потребуется настроить индивидуально на каждом устройстве.

### Полезно знать
- EXIF-метаданные (дата, геопозиция GPS) не сохраняются в конвертированных изображениях; ориентация фотографий со смартфонов аппаратно применяется к растру (пикселям).
- Файлы никогда не перезаписываются: если имя уже занято, к нему автоматически добавляется числовой индекс (`pic-…-1.webp`).
- Имена сохранённых файлов содержат компактный цифровой отпечаток оригинала: `photo-3fa9c2e1b7d04a85.webp` (первые 16 hex-символов SHA-256 исходного файла до сжатия). При повторном добавлении того же изображения — в другой заметке, при дублировании ссылки или на другом устройстве после синхронизации — плагин находит существующий файл по имени и использует его вместо повторной загрузки и кодирования. Перед связыванием кандидат строго верифицируется: размеры WebP должны совпадать с габаритами оригинала, а несжатые исходники проверяются побайтно — поэтому случайное совпадение имён исключает подстановку чужой иллюстрации. Механизм не требует синхронизации внешних баз данных (достаточно файлов самого хранилища). Если переименовать файл вручную, отпечаток теряется: в этом случае при повторной вставке файл может быть сохранён заново, но данные никогда не будут утрачены. Кроме того, после кодирования плагин ищет по всему хранилищу файлы с полностью идентичным побайтовым содержимым — это позволяет находить дубликаты, пришедшие в разных форматах (например, изображение из браузера, пересохранённое буфером обмена как иной PNG), а также файлы, созданные старыми версиями плагина без хеш-тегов. Для этой проверки с диска считываются только файлы строго совпадающего размера.
- Ссылки внутри блоков кода, встроенных фрагментов кода (инлайн) и комментариев не затрагиваются. Открытые в активном редакторе заметки автоматически сохраняются перед внесением изменений.
- Файлы WebP никогда не подвергаются повторному перекодированию, поэтому многократный запуск плагина не приводит к потере качества.

## 🧭 О проекте

Плагин разработан для решения практической задачи автора: обеспечить компактность изображений в заметках и их надёжное локальное хранение на всех устройствах. Код полностью покрыт модульными тестами, а работа энкодеров тестируется в Chromium и WebKit в рамках CI. Тем не менее, как и любое программное обеспечение, проект может содержать ошибки — ознакомьтесь с отказом от ответственности ниже и обязательно создайте резервную копию перед первой пакетной оптимизацией заметок.

## 🧪 Разработка

### Плагин
```bash
cd obsidian-plugin
npm ci
npm run typecheck
npm test               # модульные тесты (Node 22.18+)
npm run test:browser   # тестирование энкодеров в Chromium и WebKit (требуются браузеры Playwright)
npm run build          # сборка main.js
```
Релизы публикуются автоматически через CI при изменении версии в `manifest.json` (синхронизируйте версию с `package.json`); версии с суффиксом (например, `2.0.0-beta.3`) публикуются как пре-релизы (pre-release).

CI (`.github/workflows/ci.yml`) выполняет полный набор проверок, включая запуск энкодеров в окружениях Chromium и WebKit.
